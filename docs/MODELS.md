# 3D models

The command hub and the rack housing every station sits in are built in Blender from scripts (see "The Blender pipeline" below). The station props and the body figure are built from simple shapes in code, so they work without any files. Real models can replace them without code changes.

## Adding a model

1. Export the model as **glTF binary (`.glb`)** or `.gltf`. Blender: File > Export > glTF 2.0, format "glTF Binary". Keep it under about 5 MB; apply scale and rotation before export.
2. Put the file in `lab/public/models/`.
3. Add an entry to `lab/public/models/models.json`:

```json
{
  "models": [
    { "file": "medical_rack.glb", "replace": "medical", "scale": 1, "position": [0, 0, 0], "rotationY": 0 },
    { "file": "astronaut.glb", "replace": "body" },
    { "file": "treadmill.glb", "position": [0.4, -0.55, 1.2], "rotationY": 1.57 }
  ]
}
```

4. Run `npm run dev` in `lab/` and open the station. If the file fails to load, the console says so and the built-in shapes stay.

## What each field does

| Field | Meaning |
|---|---|
| `file` | File name inside `lab/public/models/` |
| `replace` | Optional. `medical`, `air`, `galley`, `radiation`, `body`, `clock`, `evidence` or `board`. Hides that station's built-in props and puts the model in its place. Parts that show live data stay: the medical and galley screens, the air readout, fan and airflow, the radiation globe and screen. |
| `position` | Metres. With `replace`, relative to the station (x right, y up, z out of the wall). Without it, in hub coordinates (origin at the centre, y up, -z towards the windows). |
| `rotationY` | Radians around the vertical axis |
| `scale` | Uniform scale |

## The body figure

Name the meshes (or their parent nodes) so they include one of these words, in any case: `brain`, `eyes`, `heart`, `lungs`, `gut`, `bones`, `muscles`, `immune`. Those meshes become clickable and take the status colours (green, amber, coral). For example `Heart`, `heart_mesh`, `Bones_Spine` all work. A model with no named parts is shown as a see-through shell with the built-in organs inside it, still clickable.

## Sizes for reference

The hub is a 12-sided drum about 6.4 m across and 2.85 m from floor to ceiling (3.3 m under the light well). Positions without `replace` are in hub coordinates: origin at the centre, y up, -z towards the observation windows. Station racks are about 1 m wide and 1.25 m high. The body figure is about 1.2 m tall standing on its pad.

## The Blender pipeline

Everything in the cabin that is not a live station is generated by Python scripts in `lab/blender/`, run headless in Blender (built and tested with Blender 5.2). No hand-made `.blend` file is needed; the scripts are the source.

| Script | Makes |
|---|---|
| `textures.py` | Tileable PBR sets (colour, roughness, normal) for paint, cool paint, brushed metal, rubber, polymer and vent mesh in `public/textures/pbr/` |
| `kit.py` | Shared geometry helpers (boxes, bevels, sweeps, lathes, text, UVs). Imported by the others |
| `hub.py` | The command hub: a 12-sided drum with a three-pane observation gallery and console, station bays (kick panel, backdrop, cabinets, lit soffit with the bay's name), corner ribs with light strips, the airlock, the floor with the central pedestal and the evidence plinth, and the ceiling with its light well. Saves `blender/out/hub.blend` |
| `bake.py` | Lights the hub, bakes the diffuse lightmap with Cycles, renders the reflection probe and exports the hub |
| `station_rack.py` | The ISS-style rack housing that frames each station. Exports `public/models/station_rack.glb` |

Rebuild from `lab/` (put Blender on your PATH, or use the full path to `blender.exe`):

```
blender -b --factory-startup -P blender/textures.py
blender -b --factory-startup -P blender/hub.py
blender -b blender/out/hub.blend -P blender/bake.py -- bake probe export
blender -b --factory-startup -P blender/station_rack.py
```

`bake.py` options after `--`: `preview` renders check images to `blender/out/`, `bake` writes `public/textures/hub_lightmap.jpg` and `.json`, `probe` writes `public/textures/hub_probe.hdr`, `export` writes `public/models/hub.glb` (Draco compressed), `samples=N` sets the bake samples. A full bake on a recent NVIDIA card (OptiX) takes about two minutes; on a CPU, much longer.

How the app uses the output (`src/scene/station.js`):

- The hub's walls are lit only by the baked lightmap (UV channel 2) and reflect the probe. Live lights are switched off for them in the shader, so the bake is not lit twice.
- The live stations, props and the body figure use real-time lights and shadows plus the same probe, so they sit in the same light.
- Materials are matched by name (`M_paint`, `M_brushed`, ...). Renaming a material in `hub.py` means updating the recipe list in `station.js`.
- The floor plan (facet angles, where each station hangs, the window opening, the two plinths) lives in `src/scene/layout.js` and is repeated at the top of `hub.py`; change both together.
- The ceiling is its own object (`HubCeiling`), so the app can hide it for the cutaway overview.
- If `hub.glb` fails to load, the app shows a plain stand-in drum (`buildFallbackHub` in `layout.js`).

`blender/out/` holds intermediate files and is not committed.
