## Form fields
1. **Project Name**: Sol Lab
2. **High-Level Project Summary**: what it is, how it answers the challenge, why it matters (draft from `docs/PITCH.md`, one paragraph)
3. **Link to Project Demo**: public link (YouTube unlisted or Google Drive "anyone with link"), no login
4. **Link to Final Project**: public link, no login. **Blocked now**: the repo is private (404 when signed out) and GitHub Pages is not on. Owner: make the repo public, then Settings > Pages > Source: GitHub Actions. Then test the link in a private window.
5. **Detailed Project Description**: what it does, how it works, benefits, goals, tools (Vite, three.js, cannon-es, satellite.js, Python analyses)
6. **Use of Super Intelligence (SI)**: the rules' new name for AI. Not shown to judges, but SI-made images/video need a visible watermark, and SI-made code/text must be acknowledged in text and metadata. The rules also say SI "should not be used to come up with your idea". Describe honestly what the team decided and what Claude Code did; do not overstate either.
7. **NASA Data**: OSDR RadLab (DOSTEL-1, REM), OSDR Environmental Data App (ISS cabin CO2, temperature, humidity), OSD-569 and OSD-575 (Inspiration4 bloodwork), Human Research Program hazard framework
8. **Space Agency Partner Data and Other References**: DLR DOSTEL (via OSDR), Baigutanova et al. 2025 sleep diaries (CC BY), USDA FoodData Central, CelesTrak elements, every code library and font (three.js, cannon-es, satellite.js, GSAP, Vite, Archivo, Barlow, Permanent Marker), any textures; full list in CREDITS. Partner data is encouraged, not required.

Also allowed: images on the page (JPG/PNG/GIF up to 10 MB). Videos and documents only as links.

## Judging: 5 criteria, each 1 to 5
**Impact, Creativity, Validity, Relevance, Presentation.**
- *Validity* includes scientific grounding, feasibility, completeness and **usability**.
- *Relevance* rewards NASA data used as a core part, not decoration: our strongest point.
- *Presentation* is helped by a strong demo.
- Most of the score comes from the project page itself, so the written fields matter more than the demo.
